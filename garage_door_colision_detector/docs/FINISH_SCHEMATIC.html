Finish the schematic: wiring first, ERC second

10 September 2026. Based on the 20:17 compiler report and a fresh read-only audit of the saved native sheets. This is an execution guide, not a claim that the schematic is finished.

Actual wiring gaps found

The active pin ends of C1/C5 and C2/C3/C4/C6 are not reached by the existing wires. All twelve capacitor pins appear unnamed in the saved geometric connectivity audit. The repair below adds the missing connections while retaining existing components, wires and library mappings.

Correction to the previous diagnosis: each capacitor has two symbol display modes, with one pin 1 and one pin 2 in each mode. They are not duplicate active pins. Do not run the archived RepairCapacitorConnections script: its proposed pin deletion was incorrect.

1. Run the native wiring repair

  1. Open the current workspace, then File → Save All.
  2. Choose File → Run Script → Browse → From File.
  3. Open SchematicFinish.PrjScr.
  4. Expand SchematicFinish.pas. By default, run RepairInputFilterConnections to repair only C2/C3/C4/C6.
  5. C1/C5 were previously deferred. Only if you now approve including them, run RepairAllSixCapacitorConnections instead. It repairs both bulk capacitors plus all four filters. Neither entry removes pins.
  6. On completion, run Validate PCB Project. Send the messages and the new hardware/altium/History/cap-wiring-YYYYMMDD-HHMMSS/report.txt.

Preflight requires saved documents and the expected component identities, pin geometry and nearby wires. A timestamped native backup is made before any intended edits. Exact added segments are skipped on rerun. If it stops, send the error; do not repeatedly retry or overwrite backups. Some sheets may already have saved before a later failure; the report records this.

The geometric test predicts all twelve intended capacitor connections, no new shorts and no changed non-capacitor nets. This has not yet been compiled or executed in your Altium session. No PCB, component, model or ERC changes are made by this script.

2. Allow the two valid GPIO/port combinations

The six IO-pin/port warnings concern bidirectional-capable ESP32 GPIOs used in specific directions. Preserve their real electrical type and the directional sheet ports.

  1. Open Project → Project Options → Connection Matrix.
  2. At IO Pin ↔ Input Port, change the severity to No Report.
  3. At IO Pin ↔ Output Port, change it to No Report.
  4. Follow the dialog's color legend and cycling controls. Change only those two combinations, not an entire row or all ERC rules. Apply and validate again.

This permits those combinations project-wide, not arbitrary output-to-output connections. GPIO34/35 remain Input. Their earlier electrical-type repair already succeeded.

3. Add specific exceptions for verified conditions

In Messages, right-click the relevant net violation → Place Specific No ERC for this violation. Place the marker on the affected wire or pin hotspot, then press Escape. In its Properties, verify Suppress Specific Violations, not Suppress All. Select only the justified violation types below. Revalidate after each group; one condition can produce multiple messages.

The EN messages refer to one pin, not three independent faults. Specific No ERC is only offered for supported net-related messages. If a command is absent, do not choose a global suppression; send that screen. Scope extra violation types through the marker's Specific Violations dialog.

These exceptions do not repair wiring. First complete step 1, then verify its saved results. Leave other checks enabled. Existing unnamed/unused ESP32 header pins are not automatically faults.
