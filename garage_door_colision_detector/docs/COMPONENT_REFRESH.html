Real components: schematic refresh

10 September 2026 · all six saved sheets, 60 component instances.

Prepared, not applied in Altium yet. The generated native script must be run in Altium and its report inspected. Native compilation/runtime and 3D appearance have not been verified here. The original SchDoc/PcbDoc files have not been rewritten by this preparation tool.

What this pass changes

  • 40 symbol appearances refreshed: Celestial capacitor, polarized capacitor, diode, TVS, fuse, optocoupler, MOSFET and switch artwork; project-authored IEC resistor variants with values inside the rectangles.
  • Every component becomes a reusable part-specific entry in a native local SchLib. Purchasing identity, original electrical pins (including alternative views), component UID and footprint mapping are retained. Sheet wires, ports and sheet symbols are not redrawn.
  • Inherited example metadata is cleaned up. Existing footprint links are pointed at files in the current repository. Source artwork is attributed to Celestial/Mark Harris; adapted symbol leads are explicitly identified as project changes.
  • Original pin positions are preserved with non-electrical symbol lead extensions, so this is not a blind database-library replacement. Generated library entries are layout-view variants, not 60 different purchasing parts. Manufacturer Part Number remains the BOM purchasing key.

Run in Altium

  1. Use File → Save All. If you have changed component identities, pins or footprints since this audit, regenerate the package first; it deliberately refuses mismatches.
  2. Open ComponentRefresh.PrjScr using File → Open.
  3. Choose File → Run Script and select ComponentRefresh.pas → RunComponentRefresh.
  4. The script stages clones, checks the existing pin identities and matching footprint pad names, then backs up all six sheets. Only after preflight does it save the curated SchLib and replace the schematic instances. The overview sheet is not edited.
  5. Read hardware/altium/History/component-refresh-<timestamp>/report.txt. A STOP or compiler error is not completion; send its exact message. If APPLY_BEGIN exists without COMPLETE, some sheets may already have changed. Restore those sheets from the same folder after closing their Altium tabs.
  6. Inspect the sheets, then Project → Validate PCB Project. From a schematic, Design → Update PCB Document opens the ECO; validate and review before executing. Saving a schematic alone does not update the PCB.

What a rectangle does—and does not—mean

The supplied ESP32 symbol has a legitimate rectangular outline. Resistor boxes are intentional IEC symbols. Sheet symbols are hierarchical page links. None should be deleted merely because it is rectangular. The issue addressed here is untraceable artwork, stale part metadata and broken library references.

Limits: do not call this a finished PCB

  • A footprint containing a 3D body may still have a crude or incorrect body. The script reports body counts but does not certify shape, orientation, mounting height or fit. It never creates grey stand-in cuboids to claim completion.
  • The Omron heads and MEAN WELL adapters remain external equipment with no controller-PCB pads. Their existing part-specific symbols are retained; manufacturer mechanical CAD is not supplied by this pass.
  • SS34 retains its current diode symbol; a dedicated Schottky glyph is still a follow-up. No different electrical device was substituted for appearance.
  • Known electrical follow-ups, including the capacitor wire audit, remain separate. Pin preservation preserves existing circuit defects too; it is not an ERC pass.
  • PCB footprints and 3D bodies are not directly edited here. The transmitter PCB section, final board sizes and mechanical mounting remain unfinished.

Sources and recovery

Imported files are copied byte-for-byte from your installed Celestial repository to hardware/altium/lib/reviewed-sources/. Their original SHA-256 hashes, pin mappings and the saved-document identities are in manifest.json. Celestial licensing and attribution are preserved in the upstream README. Sources: Celestial library, Altium native schematic API.

The generated library is stored in hardware/altium/lib/reviewed/ReviewedComponents_<timestamp>.SchLib. Add that file to the PCB project through Add Existing to Project if desired; every placed component already points to it. Keep the library with the project. No original design file is deleted.
